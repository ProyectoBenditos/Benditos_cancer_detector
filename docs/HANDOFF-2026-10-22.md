## 4. Cómo ejecutarlo en otro equipo

### Accesos y archivos necesarios

- Obtener del responsable del proyecto las variables de Supabase por un canal privado; nunca copiar valores a esta documentación.
- Obtener los tres `.pth` de OncoScan del propietario de modelos mediante almacenamiento privado autorizado. No están versionados en Git. Verificar SHA-256 contra el inventario antes de cargarlos.
- Mantener `xgb_head_v2.json` y el módulo de arquitectura en las rutas actuales; el runtime depende de ellas.
- Descargar CTChest y el checkpoint MONAI mediante el script con checksum. No hace falta usar datos de pacientes para verificar el montaje.

### Entorno comprobado y limitaciones de instalación

Se ejecutó en Windows, Node 24.14.0, pnpm 12.3.4, API Python 3.14 y worker Python 3.11. Worker: PyTorch 2.6.0+cu124, torchvision 0.21.0+cu124, MONAI 1.4.0 y XGBoost 3.2.0. GPU GTX 1650 4 GB; RAM física aproximada 16 GiB. Las versiones completas del worker están en el lock ML.

**Instalación limpia pendiente:** `apps/api/requirements.txt` no declara NiBabel/SciPy, aunque el flujo NIfTI y las pruebas geométricas los necesitan. Además fija NumPy 1.26.4; no asumir que ese requirements instala sobre Python 3.14. Para una nueva instalación se propone API Python 3.11, instalando también NiBabel 5.3.2 y SciPy 1.15.3. Ese montaje de API desde cero debe verificarse y sus dependencias deben quedar declaradas antes de publicar.

`pnpm-lock.yaml` existe localmente pero está ignorado y no versionado; `pnpm-workspace.yaml` contiene valores de ejemplo en `allowBuilds`. Quien cierre el empaquetado debe corregir el archivo y fijar un único flujo de instalación y lockfile. El comando de pruebas de la raíz no ejecuta las suites reales: ejecutarlas en cada app.

### Secuencia de preparación

Desde la raíz, con Python 3.11 instalado y las variables privadas ya configuradas. Estos son los pasos de instalación propuestos para el receptor; no se ha hecho una segunda instalación independiente:

```powershell
py -3.11 -m venv apps/api/.venv
.\apps\api\.venv\Scripts\python.exe -m pip install -r apps/api/requirements.txt -r apps/api/requirements-dev.txt
.\apps\api\.venv\Scripts\python.exe -m pip install nibabel==5.3.2 scipy==1.15.3

py -3.11 -m venv apps/api/.venv-ml
.\apps\api\.venv-ml\Scripts\python.exe -m pip install torch==2.6.0 torchvision==0.21.0 --index-url https://download.pytorch.org/whl/cu124
.\apps\api\.venv-ml\Scripts\python.exe -m pip install -r apps/api/requirements-ml.txt
.\apps\api\.venv-ml\Scripts\python.exe -m pip check
```

Instalar la web desde `apps/web` con el gestor/lock revisado, configurar `apps/web/.env.local` y `apps/api/.env`, restaurar los pesos privados y después ejecutar:

```powershell
.\apps\api\.venv-ml\Scripts\python.exe scripts/prepare_lung_demo.py
powershell -ExecutionPolicy Bypass -File scripts/start_local_services.ps1
```

Abrir http://localhost:3000/demo/pulmon-3d. El script de arranque conserva servicios que ya escuchan: comprobar `/health` del worker para no confundir un proceso anterior con el nuevo. La API usa `/api/v1/health`, no `/health`.

Para comparar los archivos recibidos con el snapshot de esta entrega, antes de modificarlos:

```powershell
py -3.11 scripts/verify_volume_handoff.py
```

El verificador comprueba presencia y hashes, con salida distinta de cero si falta o cambió un archivo obligatorio. Los textos marcados `lf_text` normalizan CRLF a LF antes de calcular SHA-256 para admitir checkouts de Windows y Linux; los binarios se comparan byte a byte. No ejecuta inferencia, no accede a Supabase y no acredita calidad clínica. Un cambio intencional se registra en una entrega nueva; no regenerar el snapshot para ocultar diferencias.

## 5. Entradas, salidas y trazabilidad

El alcance comprobado es una TC pública CTChest, no una cohorte clínica. Una unidad de procesamiento es un volumen CT con variables clínicas asociadas. Se acepta una serie ZIP de cortes CT físicamente compatibles o un NIfTI 3D. Un DICOM de un solo corte y una imagen PNG/JPG sirven para clasificación 2D, no contienen un pulmón 3D completo. Enhanced multiframe con geometría por frame todavía se rechaza explícitamente en el nuevo lector volumétrico.

En ZIP se debe seleccionar una sola serie coherente; queda pendiente robustecer la selección por `SeriesInstanceUID`, el filtrado de scouts y los límites de descompresión también en la subida inicial. El límite de 1,5 GB del lector volumétrico no protege por sí solo la fase de subida anterior.

La cadena de referencia es:

```text
CTChest NRRD con SHA-256
  → conversión LPS/RAS a NIfTI
  → lectura canónica de HU y espaciado
  → segmentación MONAI 3D / HiResCAM neuronal por corte
  → máscara, TC y calor sobre rejilla de render común
  → tres atlas + manifiesto de procedencia
  → visor WebGL2 y evidencias de comprobación
```

| Ubicación | Papel | Tratamiento |
| --- | --- | --- |
| `samples/real-lung/CT-chest.nrrd` | Fuente pública verificada. | Regenerable por descarga con checksum. |
| `samples/real-lung/CT-chest.nii.gz` | Conversión de la fuente pública. | Regenerable; comparar fuente y geometría, no prometer hash idéntico de compresión. |
| `docs/modelo-v2-densenet/weights/` | Checkpoints existentes OncoScan. | `.pth` privados fuera de Git; obtener del propietario, no reentrenar para reproducir. |
| `apps/api/.cache/models/` | Checkpoint MONAI descargado. | Verificar MD5/SHA-256; procedencia/licencia en dossier. |
| `apps/api/.cache/lung-masks/` | Cache de máscaras nativas. | Privado por contener derivados de estudios; no compartir entero. |
| `apps/api/.cache/volumes/` | Artefactos por estudio y versión. | Privado; falta política operativa de retención y borrado. |
| `apps/web/public/demo/lung-ct/` | Única muestra pública de esta entrega. | Solo CTChest pública y sus derivados. Nunca mover aquí estudios de pacientes. |
| `docs/volume-rendering/real-ct/` | Evidencias visuales y registros. | Demostración pública, no validación de una población. |

## 8. Decisiones que conviene conservar

- El aspecto inicial de pilares tenía dos causas: datos sintéticos con secciones repetidas y errores del renderizador. Se corrigieron escala física por espaciado, normales por gradiente central, iluminación, transferencia/opacidad y muestreo del atlas sin mezclar tiles. También se eliminó la dependencia de 30 cortes fijos y de coordenadas supuestas sobre una matriz de 128 píxeles.
- Se actualizó el generador de fantomas para variar las secciones a lo largo de Z. Esas muestras siguen siendo sintéticas; la referencia actual de realismo es CTChest y no el fantoma. Las capturas anteriores permanecen como antecedentes en `docs/volume-rendering/`.
- Se usa TC real, no una malla genérica descargada, para poder registrar anatomía y atribución del estudio.
- Se aisló Python ML 3.11 del entorno API 3.14 existente para instalar PyTorch/MONAI compatibles.
- Primeras máscaras parciales se detectaron visualmente. Se corrigió el relleno fuera del FOV y se reprodujeron CropForeground/GaussianSmooth y el contexto 96³ del entrenamiento oficial. No volver a una receta abreviada solo porque produce las cinco etiquetas.
- Una máscara desalineada no se corrige dibujando límites lobares geométricos ni modificando colores.
- El movimiento ilustrativo y la atribución por corte se nombran como tales; no se presentaron como fisiología medida, detector 3D o segmentación tumoral.
- Se reservó `public/demo` para la fuente pública. Los caches de pacientes permanecen privados y requieren política de borrado antes de operar en producción.
